# Power BI Guide: De-Millimanize Dashboard

This guide covers how to build, publish and check the report. It follows the original specification (Michael's prompt), merged with what we learned in this project. The model's column names come from `extract/tables.py`. **Don't rename tables or columns.**

| File | What it is |
|---|---|
| `DeMillimanize.model.tmdl` | Model script: tables, Power Query, DimDate, measures, relationships and the RLS role. It is generated by `python run.py tmdl`, so **don't edit it by hand**. Edit `make_model_script.py` instead. |
| `make_report_pages.py` | Writes the 4 report pages into `DeMillimanize.Report/definition/pages`. Run `python run.py pages` with Power BI Desktop **closed**. It replaces those pages, so make visual changes in the script or expect them to be overwritten. |
| `DeMillimanize.theme.json` | Importable theme with the colors and fonts below |
| `../sample_data/DeMillimanize Requests.mock.xlsx` | **Fake** workbook for building the report before real data exists. Create it with `python run.py mock`. |

> **Status:** Nothing in the report has been built or opened in Power BI yet. The model script and theme are untested in Power BI Desktop. If TMDL view reports an error, note the line number and fix it in `make_model_script.py`.

---

## 1. Set up the model (about 15 minutes)

1. Run `python run.py mock` (from the project folder) to create the fake workbook.
2. Open Power BI Desktop, start a **blank report**, and save it as a **Power BI Project (`.pbip`)** in `powerbi/`.
   In recent Desktop versions (for example 2.159), PBIP save and **TMDL view** are built in, so there's nothing to turn on. In older versions, go to *File > Options > Preview features*, turn on **Power BI Project (.pbip) save option**, **Store semantic model using TMDL format** and **TMDL view**, then restart Desktop.
3. Open **TMDL view** (left rail), click **+ New tab**, paste the whole contents of `DeMillimanize.model.tmdl`, and click **Apply**.
4. Click **Refresh** (Home ribbon). Power BI asks for file credentials. Choose **Windows** for a file path, or **Organizational account** for a SharePoint URL.
5. *View > Themes > Browse for themes* and pick `DeMillimanize.theme.json`.
6. *File > Options and settings > Options > Current File > Data Load* → **untick Auto date/time**. The model has its own DimDate. Without this step, date fields show as "2K Qtr 1 February 10" hierarchies.
7. Check the *Model* view: there should be 4 relationships, and DimDate should be marked as the date table (the table icon shows a calendar).

**Switching to real data:** *Transform data > Edit parameters > WorkbookPath*.

- **For now:** `O:\De-Dashboard\data\DeMillimanize Requests.xlsx`, which the extract writes.
- **Later:** the SharePoint file URL, for example `https://<tenant>.sharepoint.com/sites/<CMH IT site>/Shared Documents/<folder>/DeMillimanize Requests.xlsx`.

## 2. Report pages

**Canvas:** 16:9 (1280 x 720). Use a 16 px grid with 24 px outer margins.

**Every page has the same header band**, a navy (`#12344D`) rectangle 0-56 px tall, containing:

- A text box with the page title in white Segoe UI Semibold 18.
- Four **page navigator** buttons (Insert > Buttons > Navigator > Page navigator), styled teal `#00C1A0`.
- A **Reset filters** button (Insert > Buttons > Reset). If your Desktop version has no Reset button, use a bookmark "Reset", captured with no slicer selections and *Data* only, applied to all visuals.
- A card showing `[Last Refreshed]` (no category label, white text, transparent background).
- A card showing `[Mock Data Banner]` in red. It is blank on real data.

**Sync slicers** (View > Sync slicers) across pages 2-4: Created Date, Outcome, Device Type, Department, Requester, Computer Provided To, Frequent, Match Source.

**Outcome colors are the same on every visual.** Set them once per visual under *Data colors*:

| Outcome | Color |
|---|---|
| Approved | `#2EB67D` |
| Denied | `#E5484D` |
| Pending | `#F5A623` |
| Needs Review | `#7B61FF` |

For table cells, use *Conditional formatting > Background (or Font) color > Field value > `[Outcome Color]`*.

**Accessibility:** Give every visual alt text that describes what it shows. Set tab order (View > Selection > Tab order) from top-left to bottom-right. Turn tooltips on for all charts.

## 3. Publish, refresh, share

1. **Publish** (Home > Publish) to a CMH IT workspace. A Pro license (or Premium capacity) is needed for sharing.
2. **Credentials:** In the semantic model's *Settings > Data source credentials*:
   - **SharePoint URL:** choose OAuth2 / Organizational account. No gateway is needed.
   - **Local or UNC path** (the current stage): a **gateway** is required, so move the workbook to SharePoint before publishing.
3. **Scheduled refresh:** The extract runs at 05:30 and 12:30. Schedule the Power BI refresh for **06:00 and 13:00** in the local time zone.
4. **Getting the workbook onto SharePoint:** The extract writes locally today. *Still to decide (see OVERVIEW.md):* either sync the SharePoint folder with OneDrive on the extract machine and point `DEDASH_DATA_DIR` at it, or add an upload step.
5. **Share:**
   - Give **Viewer** access to named CMH IT people or a security group only.
   - Don't use "Publish to web" or org-wide links.
   - The SharePoint library's permissions separately control who can open the workbook itself, so restrict that library the same way.
6. **RLS:** In the semantic model's *Security*, add the program owners and viewers to the **Program Owners** role, which sees all rows. RLS only applies to Viewers; workspace Admins, Members and Contributors bypass it.

## 4. Validation checklist

Tick each item and record the date in OVERVIEW.md.

- [ ] The row counts in Power BI match the workbook for every table: Requests, People, PersonRequests, FormAnswers and RunLog. Use a card with `COUNTROWS`, or Excel's table row count.
- [ ] With mock data, searching **Jane Example** shows 3 requests (Role = Recipient), the **FREQUENT** banner, and a shortest gap of 99 days.
- [ ] With mock data, searching **Alex Tech** shows the forms he filed (Role = Requester) and Technician = Yes. He is **not** flagged as Frequent.
- [ ] A real person known to have requested before shows every ticket, both as requester and as recipient, and the ticket links open the right Freshservice tickets.
- [ ] `Frequent (Requester)` and `Frequent (Recipient)` in Power BI match the workbook for five sampled tickets.
- [ ] Outcome colors are the same on every page.
- [ ] Refresh succeeds in Desktop and in the Service, and **Last refreshed** changes after a new extract run.
- [ ] The refresh-health card turns red when the latest RunLog row is Failed. The mock data has a failed run to check this.
- [ ] **Mock Data Banner** is blank when WorkbookPath points to the real workbook.
- [ ] A Viewer outside the share list can't open the report or the workbook.

## 5. Assumptions to confirm

1. The final SharePoint site, library and folder for the workbook, and how the extract machine writes to it (OneDrive sync or upload).
2. Ticket links use `https://milliman-helpdesk.freshservice.com/a/tickets/<id>`. Should they use the `hd.milliman.com` portal instead? Change this with `DEDASH_TICKET_URL_BASE`.
3. **Department** is the **practice code from Active Directory** (for example `CMH`), found by email using SPARK's method. Freshservice department reads return 403 with our key. Requests[Department] is the practice of the person receiving the device; if that's unknown, it falls back to the ticket's Freshservice department. People[Department] is each person's own AD practice.
4. Status names come from Freshservice ticket fields. If those can't be read, the documented defaults are used: 2 Open, 3 Pending, 4 Resolved, 5 Closed.
5. The approvals API path `/tickets/{id}/approvals` and its fields haven't been seen on this account yet. Run the probe to confirm them.
6. Whether archived tickets are returned by the ticket list API.
7. Device Type is derived from the model name (ThinkPad, Latitude and similar = Laptop; ThinkCentre, OptiPlex and similar = Desktop). Anything else is "Unknown".
8. Holiday shading uses a line with shaded area. If your Desktop version doesn't allow shading on combo-chart lines, use the heatmap on page 3 instead.
